# 数字员工能力闭环标准（员工 ↔ 技能 ↔ 工具 ↔ MCP 注册/发现/权限）

> 起草：2026-08-15 · 依据：`server/staff/staffChatExecutor.ts`、`server/staff/seedStaffDeck.ts`、
> `server/dao/staff/staffSkillDao.ts`、`server/routes/staff/`（40 张 `sd_*` 表）
> 目标：**新员工接入 ≤ 半天**；能力清单 LLM 可自动发现。

---

## 1. 现状装配链路（事实基线）

一次员工对话的执行装配（`staffChatExecutor.ts`）：

```
员工(agent) 会话
  ├─ 技能注入：agent 资源绑定(agent_resource_bindings, type='skill')
  │     → skillDao.getSkillBySkillId → SKILL.md 内容物化注入上下文
  ├─ 工具注册：getBuiltinToolDefinitions（全局内置）+ getSkillToolDefinitions（技能桥，应用 builtin status patches）
  ├─ 程序技能门控：staffSkillGating.resolveStaffSkillPermissionConfig（仅当员工工具目录存在 tool_type='skill' 时生效）
  ├─ MCP 隔离：员工自有 mcp_servers 配置（tenant_id 隔离，per-call 实例，与全局 mcpClientManager 解耦）
  ├─ HTTP 工具：staffHttpToolBridge（允许私网，30s，与 web_api_call 隔离）
  └─ 执行：ReActExecutor（executionMode=REACT）→ 事件流回前端
```

数据表（`server/db-staff.ts`）：`sd_agents` / `sd_agent_resource_bindings`（skill/mcp/tool 三类绑定）
/ `sd_skills`+`sd_skill_versions` / `sd_general_skills` / `sd_tools` / `sd_mcp_servers` / `sd_agent_skill_branches`。

## 2. 能力注册标准（谁登记什么）

| 能力类别 | 登记位置 | 绑定方式 | 隔离边界 |
|---|---|---|---|
| 技能（SOP/领域知识） | `sd_skills`（content=SKILL.md）+ `sd_agent_resource_bindings(type='skill')` | 员工↔技能 N:N | tenant_id |
| 工具（内置+技能桥） | 全局 `toolRegistry` + `skillToolBridge`（builtin patches 过滤） | 员工目录 `sd_tools(tool_type='skill')` 门控 | tenant_id + agent |
| MCP 服务 | `sd_mcp_servers`（tenant_id）+ `sd_agent_resource_bindings(type='mcp')` | 员工↔MCP N:N，per-call 实例 | tenant_id（强隔离） |
| HTTP 工具 | `sd_tools`（`staffHttpToolBridge` 消费） | 员工工具目录 | tenant_id |
| 知识/记忆 | `sd_knowledge_chunks`（tenant/agent 归属） | 检索注入 | tenant_id + agent |

**注册动作 = 1 行绑定**：`INSERT INTO sd_agent_resource_bindings(tenant_id, agent_id, resource_type, resource_id, ...)`。
权限语义：技能/MCP 为「显式绑定才可用」；内置工具为「员工工具目录白名单」；停用技能经 builtin patches
在工具列表/匹配/触发/执行四层拦截（R2b-3/R2b-4）。

## 3. 能力发现标准（LLM 可自动发现）

**新增端点（建议）**：`GET /api/staffdeck/agents/:agentId/capabilities`

```jsonc
{
  "agentId": "whs-001",
  "capabilities": {
    "skills":    [{ "id": "whs-skill-inventory-query", "name": "库存查询", "triggers": ["intent:inventory", "keyword:库存"] }],
    "tools":     [{ "name": "web_api_call", "description": "..." }],
    "mcps":      [{ "server": "wms-db", "tools": ["query_sql", "list_tables"] }],
    "httpTools": [{ "name": "erp_push", "method": "POST", "baseUrl": "https://..." }]
  }
}
```

- 数据来源：`sd_agent_resource_bindings` + `sd_skills`/`sd_tools`/`sd_mcp_servers` 实时聚合（不手工维护镜像）
- 消费方：① 前端「员工档案-能力清单」页；② LLM 调度器（自动选择员工分发任务）；③ 新员工接入的自检（断言清单非空）
- 技能 trigger 已由 `builtin-skill-metadata.ts` 提供语义化关键词/意图推导，可直接并入清单

## 4. 新员工接入清单（目标 ≤ 半天）

1. **建档案**：`INSERT sd_agents`（name/role/persona/llm_config）→ 复用 `seedStaffDeck.ts` 模板
2. **挂技能**：`sd_agent_resource_bindings(type='skill')` 绑定 2-3 个领域 SKILL.md（内容由
   `skills/wms_*.md` 或新建）
3. **开工具**：员工工具目录 `sd_tools` 白名单（含 tool_type='skill' 的程序技能门控开关）
4. **接 MCP**（可选）：`sd_mcp_servers` + binding（per-call 隔离，不污染全局）
5. **配渠道**：`sd_channel_bindings`（wecom/wechat/feishu 真实推送与回调，见渠道真实化）
6. **自检**：`GET /capabilities` 清单非空 → 发一条真实消息验证装配生效（技能注入 + 工具可达）

> 可演示验收：新员工从建档到「能回答领域问题 + 能调工具」全程脚本化、≤ 半天；
> 能力清单自动聚合、LLM 可直接读取做任务分发。
