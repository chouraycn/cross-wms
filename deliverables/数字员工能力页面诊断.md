# 数字员工能力页面诊断报告（2026-07-28）

## 结论先行
你看到的两个现象，**根因都不是「代码没改」或「页面代码有 bug」**：

1. **「前端打包的软件没有看到变化」** = 运行态问题（跑的是旧打包产物 / WKWebView 缓存 / 或看的页面本轮本就没改视觉）。**代码改动已确证进入打包产物 `dist`。**
2. **「还有很多按钮报错」** = 后端 API 不可达。实测所有 `/api/staffdeck/*` 请求返回 **502 / 连接失败**。页面按钮（加载列表、保存、删除、同步工具、运行技能等）的「报错」全部是 `notify.error(error.message)` 型的 **API 调用失败 toast**，不是代码崩溃。

### 2. 后端 API 不可达（按钮报错的直接原因）

## 二、为什么会是这样

### 按钮报错（核心）
前端 API base 是相对路径 `/api/staffdeck`，依赖同源后端（Express，dev 在 3001）。
后端没起来 / 卡在启动 → 所有 API 请求失败 → 按钮全部 `notify.error`。
这是**全局现象**（不只能力页），因为工具同步、技能运行、保存、删除等按钮都走 API。

### 没看到变化
- 若运行的是**旧 DMG / 旧 dist**（本轮改动前打包）→ 看不到新增的「能力演示」带、capability 图片、plaza 预览等。
- 即使重新打包，**WKWebView 缓存**（项目已知问题：pywebview 本地 HTTP server 需 no-cache headers）会让前端加载旧 JS，看不到刷新。
- 若你访问的是 **AgentsPage（`/enterprise/agents`）或 Dashboard**，本轮**没改它们的视觉**（我们改的是 EmployeeGalleryPage / WorkRecordTab / OpenPlatformPage / TutorialPage / LoginPage）→ 也会觉得「没变化」。

## 三、修复 / 验证步骤

### A. 先确认后端是否起来（解决按钮报错）
1. `npm run dev`：看终端 `dev:server` 子进程日志，确认有 `listening on 3001`。若卡在 extensions 加载迟迟不起，需排查 server 启动（这些 ExtensionLoader ERROR 是既有债务，确认是否阻塞了 listen）。
2. 打包 DMG：打开 app 日志，确认内置后端已拉起并监听。
3. 快速自检：点按钮后看浏览器/控制台的网络请求，若 502 / ERR_CONNECTION_REFUSED → 后端未起。

### B. 让「变化」生效（解决没看到变化）
1. 重新构建并打包（改动未 commit，但 build 用工作区会包含）：
   `npm run build` → `npm run build:mac:app`
2. **清 WKWebView 缓存（关键）**：
   `rm -rf ~/Library/Caches/com.cdf.knowclow.desktop/WebKit/NetworkCache/`
3. 确认访问正确页面（本轮视觉改动所在）：
   - 员工画廊能力演示：`/workspace/gallery`（EmployeeGalleryPage）
   - 工作台能力卡：`/enterprise/dashboard` → WorkRecordTab
   - 开放平台预览：`/enterprise/open-platform`（OpenPlatformPage）
