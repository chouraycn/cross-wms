### 4.2 统一规范（Card→Box+border 扁平）

样板来源：`ExtensionsPage` / `CenterPage`（已统一）的 section 容器写法。

**迁移模式**（以 TriggersPage / TtsSettingsPage 为代表，其 Card 仅作 section 容器）：

```tsx
// 前
<Card sx={{ bgcolor: gs.bgPanel }}>
  <CardContent>
    <Typography variant="h6" mb={2}>标题</Typography>
    ...
  </CardContent>
</Card>

// 后
<Box sx={{ bgcolor: gs.bgPanel, border: '1px solid', borderColor: 'divider', borderRadius: 2, p: 2 }}>
  <Typography variant="h6" mb={2}>标题</Typography>
  ...
</Box>
```

要点：
- `borderColor: 'divider'` 暗/亮色自适应，对齐样板
- `borderRadius: 2` + `p: 2` 替代 CardContent 默认 padding
- 从 import 移除不再使用的 `Card` / `CardContent`（避免 no-unused）
- **KPI 小卡 / 功能性卡片（如 SystemMonitorPage 的 KPI 网格）保留 Card**，仅页面级 section 容器迁移

### 4.3 为什么本轮不盲改 42 页

1. **lint 阻塞风险**：`ci.yml` 的 `build-dmg` needs 含 `lint` job。原代码缩进为 4 空格/层，
   删 `CardContent` 后内容缩进需精确 −4 空格才能过 `react/jsx-indent`，逐页手工调整 42 页极易漏改 → lint 失败 → 阻塞发布。
2. **视觉回归风险**：单轮无视觉验证（无设计稿 diff）地改 42 页，易引入不一致。
3. **范围可控**：P1-2 路线图措辞是"推进"而非"一次完成所有页面"。

  KPI 网格页（SystemMonitorPage）单独评估保留 Card
