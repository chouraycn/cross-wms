# 数字员工模块：根因修复与深度完善

> 日期：2026-07-29
> 背景：用户反馈「数字员工能力页面」打包后没变化、很多按钮报错。

## 一、两个真正的根因（非代码没改、非页面 bug）

### 根因 A：后端启动即崩溃（导致「按钮全报错 / 502」）
- 文件：`server/engine/agents/utils/html.ts`
- 现象：`syntax-highlight.ts` 顶部 eager import `decodeHtmlEntityAt`，但 `html.ts` 未导出该命名符号 → 整个后端进程 `SyntaxError` 退出，`server.listen` 永远到不了。
- 后果：所有 `/api/*` 不可达，前端代理 502，**每个走 API 的按钮都弹 `notify.error(...)` 失败提示**（这不是代码崩溃，是 API 调用失败 toast）。
- 修复：在 `html.ts` 补齐 `export function decodeHtmlEntityAt(html, index)`，从指定 `&` 解码单个 HTML 实体，未知实体返回 `null` 让调用方回退为字面 `&`。
- 验证：修复后后端成功监听 3001，数字员工全部核心/lazy 接口（`agents`/`tools`/`knowledge-bases`/`general-skills`/`execution-runtime`/`model-configs`/…）均返回 **200**。

### 根因 B：前后端响应契约错配（导致「列表恒空 / 渲染崩溃 / 看似没变化」）
- 后端统一返回包裹结构 `{ code, data, message }`（见 `server/routes/staff/*`，`mock.ts:15` 注释明确）。
- 前端 `client.ts` 却直接 `response.json()` **不解包**，且页面层处理**前后不一致**：
  - 多数页面（`EmployeeGalleryPage`/`AgentsPage`/`ToolsPage`/`GeneralSkillsPage` 列表等）把响应**当裸数组**使用 → 实际拿到的是 `{code,data,message}` 对象 → `.map is not a function` 或列表恒空。
  - 少数页面（`LoginPage`/`GeneralSkillsPage`/`ConversationLogsTab`/`KnowledgePage`/`ToolsPage` 部分调用）**手动 `.data` 解包** → 与其他页矛盾。
- 修复（在 `client.ts` 统一归一化，改动最小、风险最低）：
  1. 新增 `unwrapEnvelope<T>()`：命中 `{code,data,message}` 信封则解包返回 `data`；裸数组/普通对象原样透传。
  2. 在 `request()` 与 `keepalivePost()` 中应用解包。
  3. 修正 5 个手动 `.data` 解包调用点（去掉双重解包、并把泛型改为内层 `data` 类型）：
     - `LoginPage.tsx`（登录返回体）
     - `GeneralSkillsPage.tsx`（runtime 连接态、SkillHub 导入、运行技能 ×2）
     - `ConversationLogsTab.tsx`（反馈重分析）
     - `KnowledgePage.tsx`（知识检索 hits）
     - `ToolsPage.tsx`（MCP runtime 连接态、MCP 同步）

## 二、影响面
- 涉及 `api.*` 调用点共 27 个，全部统一为「拿到解包后的 `data`」。
- SSE 流式（`streamPost`/`streamGet`/`chatHelpers` 的 `event.data`、消息 `metadata`）不属于 HTTP 信封，**未受影响**。
- 错误体解析（`parseErrorMessage` 读 `detail/message/error`）仅作用于非 200 响应，仍正确。

## 三、验证（受沙箱内存上限约束）
- ✅ `unwrapEnvelope` 逻辑单测 5/5 通过：列表信封→数组、对象信封→对象、裸数组透传、普通对象透传、空 data 数组。
- ✅ 6 个改动文件 esbuild 转译 0 语法错误。
- ✅ 根因 A 修复后，会话早期实测后端接口全 200。
- ⚠️ 本会话沙箱 cgroup 内存极紧：`tsc`（8GB/4GB）、`vite build`、`tsx server/index.ts` 启动均被 OOM 杀（exit 137）。故**未能在本会话做全量类型检查与整后端联调**，需在用户本机 `npm run build` + `npm run dev` 复验。

## 四、用户本机复验步骤
1. 后端：`npm run dev`（看 `dev:server` 日志出现 `listening on 3001`）。
2. 前端：`npm run build` 后 `npm run build:mac:app`（或 vite preview）。
3. 清 WKWebView 缓存：`rm -rf ~/Library/Caches/com.cdf.knowclow.desktop/WebKit/NetworkCache/`（避免旧 JS 不刷新）。
4. 重点验证页：`/workspace/gallery`（EmployeeGalleryPage，含「能力演示」带）、`/enterprise/dashboard`（WorkRecordTab）、`/enterprise/open-platform`、`/enterprise/tools`、`/enterprise/general-skills`。
5. 点任意按钮：若仍报「请求失败/Backend unavailable」即后端未起；若列表正常渲染即契约修复生效。
