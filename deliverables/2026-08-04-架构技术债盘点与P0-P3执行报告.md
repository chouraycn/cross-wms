## 三、P1.1：HTTP 工具去重 —— 结论与原计划相反

### 08-03 原计划

> 删掉 `server/staff/staffHttpToolBridge.ts`，让数字员工直接用核心 `web_api_call`。

### 实际评估：这是功能 + 安全的三重倒退

| 维度 | 删掉后会发生什么 |
|---|---|
| **鉴权** | `token` / `apiKey` 现由服务端从 `auth_json` 注入。删掉后需 LLM 自行拼 `Authorization` → **密钥泄露给模型** |
| **可用性** | LLM 现在看到的是「查询库存」这样的语义化工具名 + `inputSchema`。删掉后需自己猜 URL → 幻觉率显著上升 |
| **连通性** | 核心 `web_api_call` 走域名白名单且 `dangerouslyAllowPrivateNetwork: false`。企业内网 API **直接不通** |

### 真正的重复点在执行层，且安全等级不一致

| | 核心 `handleWebApiCall` | staff `executeStaffHttpTool` |
|---|---|---|
| HTTP 发起 | **裸 `fetch`** | `fetchWithSsrFGuard` |
| SSRF 防护 | ❌ 无（仅域名白名单） | ✅ 有（含 DNS 钉扎） |
| 超时 / 截断 / JSON 解析 / 错误包装 | 各自实现一遍 | 各自实现一遍 |

### 采用方案：向上收敛，不删功能

新增 `server/infra/net/httpToolRequest.ts`，导出唯一执行原语
`executeGuardedHttpRequest()`，统一「SSRF 守卫 + 超时 + 响应读取 + JSON 解析 + 截断 + 错误包装」。

- `webTools.handleWebApiCall` 直接模式改用它 → **核心工具从裸 fetch 升级为 SSRF 守卫**（安全升级）
- `staffHttpToolBridge.executeStaffHttpTool` 改用它 → 保留鉴权预置与工具名/schema（功能保留）
- 两侧返回契约、`renderJs` 行为均保持不变，不破坏既有 prompt 与 e2e 断言

**验证**：`node build-server.mjs` → `BUILD_SUCCESS`；
对三个改动文件做定向 `tsc`（拉全量依赖图，6GB 堆）→ **exit 0，零错误**。

**engine 的测试代码比整个主前端大 7 倍。**

### 与 openclaw submodule 的耦合（185 个非测试文件抽样）

| 类别 | 数量 | 占比 |
|---|---|---|
| 与 `openclaw/src` 完全相同 | 22 | 12% |
| 同路径但已本地改动 | 102 | 55% |
| CrossWMS 本地独有 | 61 | 33% |

`openclaw/src` 有 8,997 个 `.ts`，`server/engine` 有 11,537 个 —— 本地已净增 2,540 个文件。

### 结论

1. **不宜回退为 submodule 依赖。** 88% 已分叉或本地独有，替换成本远高于收益，硬分叉是既成事实。
2. **真正的负担是上游测试。** `vitest.config.ts:70` 的 `server/engine/**/*.test.{ts,tsx}`
   把 4,137 个上游测试纳入了 `npm test`（占全部 4,895 个测试文件的 85%）。
   这同时是 `tsc` OOM（exit 137）、IDE 索引卡顿、测试耗时的共同根因。

### 建议（未执行，需你确认）

把上游测试从默认 `npm test` 拆出，新增独立入口：

```jsonc
// package.json
"test":        "vitest run --config vitest.config.ts",        // 仅业务测试（758 个）
"test:engine": "vitest run --config vitest.engine.config.ts", // 上游测试（4,137 个），CI 定期跑
```

**未直接执行的原因**：会改变覆盖率基线，可能导致

## 六、新发现：`server_dist/` 构建产物入树

`.gitignore` 有 `dist-server/` 却**漏了 `server_dist/`**（`build-server.mjs` 的 esbuild 单文件输出，
`dev:fast` 直接 `node` 它）。

后果：git 历史已累积 6 个版本的 `index.cjs`（21–31MB 各一份，**合计约 144MB**）。
今天 push `backup` 分支时 GitHub 直接告警：

```
remote: warning: File server_dist/index.cjs is 88.58 MB;
        this is larger than GitHub's recommended maximum file size of 50.00 MB
remote: warning: GH001: Large files detected. You may want to try Git LFS.
```

**已处理**：`.gitignore` 补 `server_dist/`（附原因注释防复发）+ `git rm --cached`
（仅出索引，磁盘文件保留，`dev:fast` 不受影响）。单次提交删除 647,709 行。

**未处理**：历史中已有的 ~144MB blob 需 `git filter-repo` 重写才能真正瘦身，
属破坏性操作（改写所有 commit hash，影响所有协作者），留待单独决策。
