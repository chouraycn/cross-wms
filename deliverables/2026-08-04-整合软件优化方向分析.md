## 二、优化方向（按 ROI 排序）

### 🔴 P0-1 构建产物治理 —— 最高性价比，半天见效

**现象**
`dist/` 81MB，其中 `assets/js` 75MB。DMG 稳定在 183–237MB 且随构建次数波动。

**证据**
```
dist/assets/js:  762 个 .js  =  17M
                 762 个 .map =  58M   ← 占 dist 的 72%
去重后 chunk：   174 个（即 78% 是历史构建残留）
main-*.js 有 5 个不同 hash；SkillsPage/ModelsPage/DashboardPage/AgentsPage 各 10 个
```

**根因（两个，互相独立）**

1. **`emptyOutDir` 悖论**
   `vite.config.ts:104` 设了 `emptyOutDir: false`，理由是"防止清空 `dist/staffdeck-app/` 导致 iframe 白屏"。
   代价是**主前端产物只增不减**，每次构建叠一层。
   而 `scripts/package-mac-app.sh:148` 的注释却写着 *"vite build 会清空 dist/"* ——
   **注释和配置直接矛盾**，说明这层副作用当初没被意识到。

2. **sourcemap 全量进包**
   `vite.config.ts:118` 是 `sourcemap: 'hidden'`（生成 map 但 js 内不加引用注释）。
   打包时 `package-mac-app.sh:157` 执行 `cp -R "$ROOT_DIR/dist/"* ...` —— **全量拷贝，不排除 .map**。
   脚本里确实有 `-name "*.map"` 的排除逻辑（第 348 行），但那只作用于 `$SHARED_NM`（node_modules），对 `frontend_dist` 无效。

**建议动作**
```jsonc
// 方案：调构建顺序，恢复 emptyOutDir
// package.json — 让 staffdeck 在主前端之后构建（现状已是这个顺序，可直接恢复）
"build": "tsc && vite build && npm run staffdeck:build"

// vite.config.ts
emptyOutDir: true,   // ← 恢复默认，配合上面的顺序，staffdeck-app 在其后重建

// package-mac-app.sh:157 — 拷贝时排除 sourcemap
rsync -a --exclude='*.map' "$ROOT_DIR/dist/" "$RESOURCES_DIR/frontend_dist/"
```

**预期收益**
`dist` 81M → **约 9M**；DMG 183M → **约 115M（-37%）**。
下载/安装/首次启动 I/O 全线受益。

**风险**：低。唯一要验的是 `emptyOutDir: true` 后 staffdeck-app 确实在其后重建（构建顺序已保证）。改完跑一次 `npm run build` 看 `dist/staffdeck-app/index.html` 在不在即可。

### 🟠 P1-1 双套数字员工 UI 收敛 —— 需要你拍板

**现象**
用户从不同入口会看到**两个长相完全不同的数字员工**。

**证据**

| | iframe 版 | MUI 存量版 |
|---|---|---|
| 入口 | 导航「数字员工」→ `/staffdeck` | 直接访问 `/enterprise/*` |

**这里要澄清一个铁律的边界**：
项目铁律是「数字员工前端必须用 iframe 嵌入原 StaffDeck，禁止用 MUI 重写追求复刻」。
铁律保护的是"哪个是唯一复刻实现"，**并没有要求 MUI 版继续挂在路由上对用户可达**。

**三个选项**

| 选项 | 动作 | 收益 | 代价 |
|---|---|---|---|
| A. 彻底下线（推荐） | 摘掉 `/enterprise/*` 22 条路由，删 3.2 万行 | 产品一致、包体再降、维护面砍半 | 若 iframe 版有功能缺口会暴露 |
| B. 降级兜底 | 保留代码不挂路由，留 feature flag | 可回滚 | 3.2 万行继续编译进包 |
| C. 维持现状 | —— | 0 | 双份维护 + 用户困惑持续 |

**建议先做一件事**：把 iframe 版和 MUI 版的功能点做个 diff（22 条路由逐个对照），确认 iframe 版没缺口，再决定 A 还是 B。这个 diff 我可以帮你跑。

### ✅ P2-2 SSE 客户端统一 —— 已落地，并顺手修了一个真 bug

新建 `src/utils/sse/readSseResponse.ts` 作为唯一读流原语，增强 `SSEStreamParser`（补无空格 `event:` 格式支持 + `flush()` 冲刷末行残留），两个手写解析的调用方改为复用：

| 文件 | 改动 |
|------|------|
| `src/components/staff/api/client.ts` | `streamPost`/`streamGet` 删除各自 getReader 循环，删除孤立 `parseSseBlock`（-82 行）|
| `src/pages/staff/EmployeeChatPage.tsx` | `readStaffStream` 改用 `fetchSseStream`（-70 行）|

**修复的真 bug：** `EmployeeChatPage.tsx` 原实现在流结束时**没有调用 `decoder.decode()` 做尾部 flush**。TextDecoder 在流式模式下会缓存不完整的多字节序列，当一个 UTF-8 汉字恰好跨越两个 chunk 边界、且它是最后一个字符时，**该字符会被静默丢弃**。这类 bug 只在特定长度的回复上偶发，极难复现定位——统一实现顺带根治。
