> 目标：将 `server/routes` 下约 1053 处裸 `res.json` 响应统一为 `{ code, data, message }` envelope，与 `respond.ts` 基建及前端 client（兼容 envelope 与裸数据）对齐。

## 1. 统一响应基建（已就绪，勿改）

`server/routes/_shared/respond.ts`：
- `ok(res, data, message='ok')` → `{ code:0, data, message }`
- `fail(res, code, message, httpStatus=400)` → `res.status(httpStatus).json({ code, data:null, message })`
- `notFound(res, message='Not found')` → `res.status(404).json({ code:404, data:null, message })`

调用方示例（已落地 `inventory.ts`）：`return respond.ok(res, payload)` / `return respond.fail(res, 40001, '参数错误')` / `return respond.notFound(res)`。

## 2. 推荐错误形态（待拍板①）

| 响应 | 形态 | HTTP 状态 | code 取值 |
|---|---|---|---|
| 成功 | `{ code:0, data, message:'ok' }` | 200 | 0 |
| 参数/业务错 | `{ code:<业务码>, data:null, message }` | 400/422 | **非 0 业务码**（建议 4xxxx=客户端错，5xxxx=服务端错） |
| 未找到 | `{ code:404, data:null, message }` | 404 | 404 |
| 服务异常 | `{ code:500, data:null, message }` | 500 | 500 |

**核心约定（需你拍板）**：`code` 是**业务码**还是**沿用 HTTP 状态码**？
- 方案 A（推荐）：`code` = 业务码（4xxxx/5xxxx 分段），HTTP 状态码保留用于传输层。前端 client 已兼容 envelope。
- 方案 B：`code` 直接等于 HTTP 状态码（如 404→code 404）。简单但丢失业务细分。

> 注意铁律：StaffDeck 嵌入前端**禁止依赖 `code` 字段**（剥包逻辑只剥 `code===0` 的成功响应，错误保留 envelope）。统一 envelope 不违反此约束。
