### 3.2 失败根因逐条定位

| 失败套件/用例 | 现象 | 根因 | 性质 |
|---|---|---|---|
| `smoke.e2e` | "服务在 60000ms 内未启动: fetch failed" | 本沙箱内存受限，engine 过大，server 启动 >60s | **环境性** |
| `performance-baseline`、`packages-integration` | Failed Suites（同启动超时） | server 启动超时，套件无法挂载 | **环境性** |
| `agents.e2e` | `Cannot find module '@openclaw-src/agents/sessions/session-manager.js'` | openclaw 子模块未构建 / `@openclaw-src` 别名未解析（正是 08-08 后那批 CI commit 在修的问题） | **环境性（子模块未 build）** |
| `groupC-smoke` ×3 | `Hook timed out in 10000ms`（beforeEach 挂载 agent-runtime router） | agent-runtime 模块重，沙箱加载 >10s | **环境性** |
| `staff.spec` ×1（UI） | `/agents` 导航 15s 超时 | localhost:5173 dev server 沙箱内未就绪 | **环境性** |

**结论**：本次 e2e 数字下滑（API 335/340、UI 6/7）**并非应用代码回归**——所有失败均为「沙箱资源受限导致 server 启动/router 挂载超时」或「openclaw 子模块未构建导致 `@openclaw-src` 别名解析失败」。在「openclaw 已 build + 资源充足」的标准 CI 环境复跑，预期回到 08-08 的 99.7% 水平。

> 旁证：server 运行期仍有非致命日志（如 `no such table: memory_vec_index`、`无可用模型`），属测试库未初始化/未配模型的预期噪声，与启动超时无因果。
